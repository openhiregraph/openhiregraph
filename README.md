# 🚀 OpenHireGraph

**OpenHireGraph** is an open-source, candidate-first **semantic talent graph** that lets recruiters find people using **natural language**, not keywords.

Instead of job postings → resumes → ATS filters, OpenHireGraph flips the model:

**Candidates publish rich, structured profiles.**  
**Recruiters search the entire talent graph semantically.**

Powered by embeddings, vectors, structured metadata, and RAG (Retrieval-Augmented Generation).

---

## 🌟 Why OpenHireGraph?

The hiring pipeline is still stuck in a world of:
- PDF resumes  
- Keyword-matching  
- Applicant Tracking Systems  
- Job boards  
- Recruiters drowning in manual search  

Meanwhile, we live in a world where LLMs can understand meaning, context, work artifacts, and intent.

OpenHireGraph rethinks the entire system:

> **Don’t force candidates to apply to jobs.  
Let companies search for talent the same way developers search code.**

---

## 🧠 What OpenHireGraph Does

- 🧭 **Natural Language Talent Search**  
  Recruiters describe what they need (“Someone who built event-driven systems, EU timezone”), and the LLM creates a query plan.

- 🔎 **Hybrid Search (Semantic + Structured)**  
  SQL filters (location, seniority, compensation) blended with vector search over candidate projects & experience.

- 📄 **RAG-Powered Explanations**  
  Candidates aren’t ranked by vibes — every match is grounded in retrieved evidence.

- 🧱 **Open, Inspectable Schema**  
  Candidates control what they publish. Recruiters transparently see why someone is a match.

- 🌍 **Public Talent Graph**  
  A shared, open standard for representing skills, experience, projects, preferences, and availability.

- 🧩 **Designed for Extensibility**  
  Plugins for GitHub, portfolios, LinkedIn exports, bootcamp pipelines, custom ingestion, etc.
